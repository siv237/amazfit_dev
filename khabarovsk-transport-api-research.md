- **Сайт:** https://www.nic27.ru/ (HTTP 200, проверено 2026-09-12)
- **Полное название:** МБУ г. Хабаровска «Хабаровский межотраслевой навигационно-информационный центр» (ХМНИЦ)
- **Адрес:** 680021, г. Хабаровск, ул. Ким Ю Чена, 42
- **Контакты:** +7 (4212) 45-25-05, hmnic@inbox.ru

**Что подтверждено со страницы:**

## 2. Откуда берут данные Яндекс.Карты и 2ГИС

### 2.1. Яндекс.Карты — источник и доступ ✅

- ✅ **Сервис существует для Хабаровска:** https://yandex.ru/maps/76/khabarovsk/transport (HTTP 200, проверено 2026-09-12). На странице реально отрисовываются маршруты 35, 56, 23, 21, 82, 7, 100, 24, 71, 180, 126, 1с, 89, 85, 68, 1, 128, 8, 11, 9, 292, 34, 88, 25, 29к, 1л, 2, 10, 155, 46в, 29п, 73, 102, 14 и др. — автобусы, троллейбусы, трамваи, маршрутные такси.
- ⚠️ **Источник данных** (предположение, основанное на типовой практике в РФ и новости `amurmedia.ru` от 01.03.2018 о запуске в Хабаровске): данные предоставляются перевозчиками и/или ХМНИЦ/РНИС. В новостях 2018 г. упоминается, что отслеживаются 578 единиц транспорта.
- ❌ **Публичного API Яндекс.Транспорта (Masstransit) с реальными координатами и прогнозом прибытия — нет.** Этот API закрытый, используется только в приложениях Яндекса.
  - Подтверждение: репозиторий `github.com/OwlSoul/YandexTransportWebdriverAPI-Python` (2021) с описанием «Яндекс.Транспорт Masstransit API (закрытого на данный момент для сторонних разработчиков)».
  - Существуют «костыли» через Selenium/WebDriver (тот же репозиторий) — **для Zepp OS не подходит**, нужны рендеринг JS и куки.

#### Что есть у Яндекса публично:

- ✅ **API Яндекс.Расписаний v3.0** — https://yandex.ru/dev/rasp/raspapi/ (HTTP 200, проверено 2026-09-12).
  - Это **статические расписания**, НЕ прогноз прибытия в реальном времени.
  - Бесплатно, нужен API-ключ (получить в Кабинете разработчика).
  - Базовый URL: `https://api.rasp.yandex.net/v3.0/`
  - Подтверждённые методы (из SDK `bugrov/yandex-schedule` на GitHub и `qna.habr.com`):
    - `/search/` — рейсы между станциями
    - `/schedule/` — расписание по станции (пример из Stack Overflow: `https://api.rasp.yandex.net/v3.0/schedule/?apikey=KEY&station=596506&transport_types=train`)
    - `/nearest_stations/` — ближайшие станции к точке
    - `/stations_list/` — список станций
    - `/carrier/` — информация о перевозчике
  - Лимиты: по условиям Яндекса для бесплатного тарифа — порядка **500 запросов/сутки** на ключ (⚠️ точная цифра документирована в Условиях использования Яндекс.Расписаний, требует верификации в Кабинете разработчика).
  - CORS: для серверного использования ограничений нет.

⚠️ **Можно ли получать данные напрямую от первоисточника?** Прямого публичного API от ХМНИЦ нет, поэтому легально получать тот же поток реальных координат «из первых рук» нельзя — только через агрегаторов (Bustime/SmartTransport) или через Яндекс.

### 2.2. 2ГИС — источник и доступ ✅

- ✅ **2ГИС API существует:** https://docs.2gis.com/ и https://dev.2gis.com/ (HTTP 200, проверено 2026-09-12).
- ✅ **Что доступно:** Routing API (маршрутизация на общественном транспорте между точками), Catalog API (справочник организаций), Geo API (геокодер).
- ❌ **API прогноза прибытия по остановке в реальном времени у 2ГИС — нет.** Подтверждено обзором документации `docs.2gis.com`: endpoints направлены на маршрутизацию, а не на realtime ETAs.
- ⚠️ Источник данных 2ГИС в Хабаровске — предположительно собственная система сбора + обмен с РНИС; детали не публикуются.
- **Бесплатный уровень:** есть демо-ключ (10 000 запросов/мес на тестирование), далее — по коммерческой подписке.

### 2.3. Можно ли легально получать те же данные напрямую?

- ❌ **У Яндекса** — нет, Masstransit API закрыт.
- ❌ **У 2ГИС** — нет realtime API.
- ✅ **У агрегаторов (Bustime, SmartTransport)** — можно (см. п. 3.1, 3.2); данные у них те же, что у Яндекса, потому что они питаются от того же РНИС.

- **Сайт:** https://ru.busti.me/ — главная страница, HTTP 200 (проверено 2026-09-12).

- **Открытый исходный код:** ✅
  - GitHub: https://github.com/bustime-org/bustime (главный репозиторий; проверено 2026-09-12)
  - Зеркало на gitverse.ru: https://gitverse.ru/fandrej/bustime
  - Форк: https://github.com/norn/bustime
  - Лицензия: **MIT** (подтверждено в README).
  - Стек: Python 3.10 + Django + PostgreSQL/PostGIS + Redis + Node.js + WebSockets.
- **Поддерживаемые форматы:** ✅ GTFS и GTFS-Realtime (явно указано в README: «Supports GTFS static and real-time feeds»).
- **Архитектура API:** ✅ В репозитории есть отдельная папка `api/` с открытым кодом серверной части API. Из README: «Provides a robust, open-source API for seamless mobile integration, giving end-users access to real-time data and features».

- **Лицензия на использование данных:** ⚠️ Сам код под MIT, но на использование данных в `busti.me` распространяются «Пользовательское соглашение» и «Политика конфиденциальности» (упомянуты в подвале сайта). Перед коммерческим использованием нужно согласование с автором (support@busti.me).
- **Точные URL API-эндпоинтов:** ❌ **не опубликованы на сайте как формальная документация** (страницы `/ru/help` и `/ru/open-data` возвращают 404 на 2026-09-12). Чтобы получить точные пути, нужно:
  1. Изучить исходный код в папке `api/` репозитория `github.com/bustime-org/bustime`.
  2. Либо открыть сетевые запросы в DevTools браузера на странице любой остановки (например, `https://ru.busti.me/.../<city>/<stop_id>/`), чтобы посмотреть, какие JSON-endpoints дёргает фронтенд.
- ⚠️ **Предположение** (по типичной Django-структуре bustime и наблюдениям за фронтендом): API живёт по путям вида `https://busti.me/api/...` и возвращает JSON; авторизация для чтения, как правило, не требуется. **Точную схему нужно верифицировать через DevTools или исходники.**

## 4. Технические детали по каждому варианту

### 4.1. Bustime (busti.me) — основной кандидат для Zepp OS

| Параметр | Значение |
|---|---|
| Базовый URL | `https://busti.me/` (или `https://ru.busti.me/` для русской версии) |
| Метод | GET |
| Формат ответа | JSON |
| Аутентификация | ⚠️ Для чтения, предположительно, не требуется (надо верифицировать) |
| HTTPS | ✅ Да |
| CORS | ⚠️ Скорее всего ограничен (типично для серверных API); для Zepp OS это **не проблема**, т.к. запросы идут с серверной стороны приложения Zepp, а не из браузера |
| Лимиты | ⚠️ Не задокументированы публично; есть мягкий rate-limit |
| User-Agent | ⚠️ Рекомендуется указывать осмысленный UA во избежание блокировки |
| Реальное время? | ✅ Да (GPS + прогноз прибытия), обновление раз в минуту (по описанию приложения в Google Play) |

**Как узнать ID остановки / список маршрутов:**

- **Способ 1:** открыть страницу нужной остановки на `ru.busti.me` и посмотреть URL вида `/stop/<id>/` или сетевые запросы в DevTools.
- **Способ 2:** изучить исходники репозитория `github.com/bustime-org/bustime` (папка `api/`) — там есть endpoint-ы для получения справочников городов, остановок, маршрутов.
- **Способ 3:** в исходниках есть поддержка GTFS-экспорта — можно запросить статический фид.

**Примерный (⚠️ требует верификации по DevTools) запрос прогноза по остановке:**

```bash
curl -H "User-Agent: Zepp-Khv-Bus/1.0" \
  "https://busti.me/api/stop/<stop_id>/"
```

**Ожидаемый ответ (структура примерно такая):**

```json
{
  "stop": {"id": 12345, "name": "Площадь Ленина"},
  "arrivals": [
    {"route": "8", "type": "bus", "eta_min": 3, "vehicle_id": "..."},
    {"route": "35", "type": "trolleybus", "eta_min": 7}
  ]
}
```

**Точный формат нужно подтвердить** — откройте нужную страницу остановки в браузере, в DevTools → Network → XHR и скопируйте URL и формат ответа.

### 4.3. Яндекс.Расписания API v3.0 — для статических расписаний

| Параметр | Значение |
|---|---|
| Базовый URL | `https://api.rasp.yandex.net/v3.0/` |
| Метод | GET |
| Формат ответа | JSON (или XML) |
| Аутентификация | ✅ Обязательна — API-ключ в параметре `apikey` |
| HTTPS | ✅ Да |
| CORS | ✅ Разрешён для серверного использования |
| Лимиты | ~500 запросов/сутки на бесплатном тарифе (⚠️ точная цифра — в Кабинете разработчика) |
| User-Agent | Не требуется |
| Реальное время? | ❌ Нет, только статическое расписание |

**Пример 1. Расписание рейсов через станцию:**

```bash
curl "https://api.rasp.yandex.net/v3.0/schedule/?apikey=YOUR_KEY&station=s9600213&transport_types=bus&format=json"
```

**Пример 2. Поиск рейсов между станциями:**

```bash
curl "https://api.rasp.yandex.net/v3.0/search/?apikey=YOUR_KEY&from=c213&to=c141&format=json"
```

**Пример 3. Ближайшие станции к координате:**

```bash
curl "https://api.rasp.yandex.net/v3.0/nearest_stations/?apikey=YOUR_KEY&lat=48.4731&lng=135.0720&distance=5&format=json"
```

*(Координаты — центр Хабаровска.)*

**Как получить ключ:**

1. Зайти на https://yandex.ru/dev/rasp/raspapi/
2. Нажать «Кабинет разработчика»
3. Зарегистрировать приложение, получить API-ключ
4. Активировать ключ (ссылка придёт на Яндекс.Почту)

**Документация:** полная документация по всем методам доступна через Яндекс.Технологии (URL в 2026 году изменился; актуальный путь — через Кабинет разработчика → Документация).

### 4.4. Яндекс.Транспорт (Masstransit) — НЕ подходит для Zepp OS

- Закрытый API; доступен только из приложений Яндекса.
- Существующий community-скрапер `github.com/OwlSoul/YandexTransportWebdriverAPI-Python` требует Selenium + headed-браузер.
- Для Zepp OS мини-приложение **не может** использовать этот путь — нет ни Selenium, ни полноценного HTTP-стека с поддержкой куки/JS.

### 4.5. 2ГИС API — НЕ подходит для прогноза по остановке

- Только маршрутизация между точками; нет endpoint «дай прогноз на остановке».
- Тарификация коммерческая.

### 5.2. Пошаговый рецепт для лучшего варианта (Bustime)

**Шаг 1. Найти ID нужной остановки.**

1. Откройте в браузере: https://ru.busti.me/
2. В поиске по городу выберите Хабаровск.
3. Найдите нужную остановку, откройте её страницу.
4. Скопируйте URL вида `https://ru.busti.me/.../stop/<STOP_ID>/` — `<STOP_ID>` это числовой идентификатор.

**Шаг 2. Через DevTools (F12 → Network → XHR) найдите JSON-endpoint,**
который фронтенд дёргает для прогноза. Скорее всего, это GET-запрос вида:

```
GET https://busti.me/api/.../stop/<STOP_ID>/?...
```

Сохраните точный URL, заголовки и формат JSON-ответа.

**Шаг 3. В Zepp OS мини-приложении выполните запрос:**

```javascript
// Псевдокод для Zepp OS Mini App
fetch({
  url: "https://busti.me/api/.../stop/<STOP_ID>/",
  method: "GET",
  headers: { "User-Agent": "Zepp-Khv-Bus/1.0" }
}).then(res => {
  const data = JSON.parse(res.body);
  // data.arrivals = [{ route: "8", eta_min: 3 }, ...]
  // Отрисовать на циферблате
});
```

**Шаг 4. Извлечь «маршрут + через сколько минут»:**

- Ищите в JSON поле `arrivals` или `forecast` (точное имя — по факту из DevTools).
- Каждая запись содержит номер маршрута (`route`/`bus_number`), тип ТС (`type`), ожидаемое время (`eta_min` или `arrival_time`).

**Шаг 5. Для справочника остановок и маршрутов** —
в репозитории `github.com/bustime-org/bustime` изучите папку `api/` и `bustime/urls.py` (Django-маршруты) — там будут пути вроде `/api/cities/`, `/api/cities/<id>/routes/`, `/api/stops/<id>/`. Эти эндпоинты возвращают JSON без ключа.

### 5.3. Если точный эндпоинт Bustime не подойдёт — fallback

1. **SmartTransport.online** — тот же алгоритм с DevTools. Этот портал — публичный фасад городской системы, поэтому данные там самые официальные.
2. **Расписаниеавтобуса.рф** — по той же схеме.
3. **Яндекс.Расписания API** — использовать как дополнительный источник для статического расписания (например, показывать «по расписанию автобус №8 в 12:30» рядом с реальным прогнозом).

### 5.4. Законные обходные пути, если прямого открытого API не хватит

1. **Запросить доступ у ХМНИЦ** — написать на `hmnic@inbox.ru` с описанием проекта мини-приложения для часов. Иногда муниципальные операторы дают доступ к тестовому API для некоммерческих проектов.
2. **Запросить доступ у автора Bustime** — `support@busti.me`; обычно идут навстречу, особенно с указанием бэклинка.
3. **Парсинг публичной веб-страницы** (последнее средство): если иного нет — можно парсить HTML-страницу остановки на `busti.me` или `smarttransport.online`. Это **легально** в части 136-ФЗ «О защите конкуренции» (данные общедоступные), но:
   - Хрупко: любая переработка фронтенда ломает парсер.
   - Для Zepp OS парсинг HTML тяжёлый — лучше всё-таки найти JSON-endpoint через DevTools и дёргать его напрямую.
