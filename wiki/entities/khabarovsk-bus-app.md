# Приложение khabarovsk-bus (Автобусы ХБР)

Мини-приложение Zepp OS (GTS 4): показывает ближайшие остановки Хабаровска (по позиции)
с ближайшим транспортом; прокрутка колесика выбирает остановку и показывает её прибытия.

- Список = **8 ближайших** остановок (из всех 930, `page/stations.js`).
- Подпись в колесике: `Остановка · Маршрут Nм` (у каждой виден её ближайший автобус).
- Позиция берётся из `currentPosition()` (интерфейс готов под GPS; сейчас резервные
  координаты **ул. Большая, 8** — 48.5000302, 135.0979337; приложение не помечает их
  как «симуляцию»).
- `app-side` умеет `GET_NEARBY` (параллельные запросы по каждой остановке → ближайший
  рейс) и `GET_FORECAST` (топ-3 прибытия для выбранной).

## Экраны (финал)

**Список** (по мотивам превью `preset/`):
- Синяя шапка (y=0..46): иконка автобуса, «Автобусы», часы **с секундами** (тикают,
  `setInterval` 1 c, см. `clockText`).
- Подзаголовок «Ближайшие остановки».
- `SCROLL_LIST`: строки `иконка + название + направление` слева, `маршрут Nм` (зелёный)
  и `расстояние` справа. Тап по строке → экран прибытий.

**Прибытия**:
- Та же синяя шапка, но шире (62): кнопка «‹», название остановки и вторая строка —
  `направление · расстояние`; часы с секундами.
- Ниже `SCROLL_LIST` «Ближайшие автобусы»: `иконка типа + маршрут` и `N мин` (зелёный).
- Тап по автобусу → третий экран.

**Автобус** (тап по конкретному рейсу):
- Крупное число — сколько минут до прибытия (green, ~150 px).
- «Следующий рейс: через N мин» (ищется среди следующих прибытий того же маршрута).
- `app-side` отдаёт до 12 прибытий, чтобы был «следующий».

**Возврат**: тап в любое место синей шапки возвращает на предыдущий экран
(шапка — кнопка-подложка под заголовком).

## Технические уроки

- **Системный статус-бар скрывается**: `hmUI.setStatusBarVisible(false)` (`@zos/ui`,
  только для квадратных экранов). Иначе он рисуется поверх синей шапки; сдвиг `y`
  не помогает.
- **Тап по строке**: `GROUP.click_func` и `click_func` на `TEXT`/`FILL_RECT` в этом
  симуляторе не срабатывают, а виджеты поверх кнопки перехватывают тап. Надёжно —
  `SCROLL_LIST` с `item_click_func` (или кнопка как единственный слой).
- **Иконки**: PNG рисовать в целевом размере (IMG не масштабирует).
- Позиция: `currentPosition()` — точка замены под GPS; сейчас резервные координаты
  ул. Большая, 8.

- Исходники: `apps/khabarovsk-bus/`
- appId: `25067`
- Сборка: `dist/25067-Автобусы_ХБР-1.0.1-*.zab` (~377 КБ)
- Скриншот: `apps/khabarovsk-bus/screenshot.png`, QR: `apps/khabarovsk-bus/preview_qr.png`

## Как работает

1. `page/index.js` — `WIDGET_PICKER` со списком остановок (`page/stops.js`, ~24 шт.).
2. При смене выбранного элемента (событие `picker_cb`) берётся `sid` остановки и
   вызывается `this.request({method:"GET_FORECAST", params:{sid}})`.
3. `app-side/index.js` делает `POST` к SmartTransport API и возвращает топ-3 прибытия.
4. На экране: `routeShortName` + минуты (`arrivalTimeInSec/60`).

## Особенности реализации

- Событие PICKER приходит как `event_type 1` (focus) с текущим `select_index`;
  реагируем на смену индекса, а не только на `event_type 2`.
- PICKER рендерится по центру экрана (поле `y` почти не влияет) — текст результата
  вынесен ниже колесика.
- Первый запрос может поймать `shake timeout` (side-service ещё поднимается) —
  добавлен авто-ретрай.
- API: `getStationForecasts.php` с токеном по умолчанию; подробности —
  [smarttransport-online.md](smarttransport-online.md).
