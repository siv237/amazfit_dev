# AGENTS.md — схема вики (Zepp OS / Amazfit GTS 4)

Этот файл — **schema** по модели «LLM Wiki». Он описывает, как устроена вики, какие
конвенции соблюдать и какие рабочие процессы выполнять при ingest, query и lint.
Человек курирует источники и задаёт вопросы; LLM пишет и поддерживает всю вики.

## Назначение

Персональная база знаний по настройке среды разработки мини-приложений и циферблатов
для часов **Amazfit GTS 4** на платформе **Zepp OS 3.5** (Ubuntu 24.04 + VS Code).
Домен: DevOps/embedded toolchain, установка, диагностика, типовые проблемы.

## Три слоя

1. **Raw sources** — `raw/`. Курируемые исходники. **Неизменяемы.** LLM читает, но
   никогда не редактирует.
2. **Wiki** — `wiki/`. Markdown-страницы, полностью создаваемые и поддерживаемые LLM.
3. **Schema** — этот файл `AGENTS.md`. Конвенции и workflow.

## Структура вики

```
wiki/
  index.md          каталог всех страниц (обновляется при каждом ingest)
  log.md            хронология операций, append-only
  overview.md       обзор домена и текущий статус среды
  sources/          по странице на каждый raw-источник (summary)
  entities/         конкретные объекты: устройство, инструменты, пакеты
  concepts/         понятия: Zepp OS, API_LEVEL, deviceSource, QR-установка
  procedures/       воспроизводимые пошаговые процедуры (setup, build, preview)
```

## Конвенции

- Язык вики — **русский**. Технические имена, команды, пути, идентификаторы — как есть.
- Имя файла — kebab-case, латиница, `.md`.
- Первая строка каждой страницы — заголовок `# Название`.
- Ниже — блок YAML frontmatter (см. ниже).
- Ссылки между страницами — относительные markdown-ссылки (`../concepts/zepp-os.md`).
- Факты, которые можно проверить командой, помечать статусом `OK` / `FAIL` / `N/A`.
- Каждое утверждение о версии/статусе должно опираться на вывод реальной команды.
- Не дублировать raw-источники: страница источника сжимает и связывает, а не копирует.

### Frontmatter

```yaml
---
type: entity | concept | procedure | source | meta
tags: [zepp-os, gts4]
status: ok | fail | partial | unknown
updated: YYYY-MM-DD
sources: [raw/promt-agent-zeppos-gts4-ubuntu.md]
---
```

## Операции

### Ingest
1. Новый файл кладётся в `raw/` и не меняется.
2. Создать `wiki/sources/<slug>.md` — краткое резюме и ключевые тезисы.
3. Обновить релевантные `entities/`, `concepts/`, `procedures/`.
4. Обновить `index.md`.
5. Дописать запись в `log.md`.
Один источник может затронуть 5-15 страниц.

### Query
1. Прочитать `index.md`, найти релевантные страницы.
2. Прочитать их, синтезировать ответ со ссылками.
3. Если ответ ценен — сохранить его как новую страницу и обновить index/log.

### Lint
Периодически проверять: противоречия, устаревшие данные, страницы-сироты,
понятия без своей страницы, пропущенные ссылки, пробелы в данных. Результат — в log.md.

## Журнал (log.md)

Формат записи (важен префикс для `grep "^## \["`):

```
## [YYYY-MM-DD] ingest | Название источника
## [YYYY-MM-DD] setup | Шаг N — название
## [YYYY-MM-DD] lint | краткий итог
```
