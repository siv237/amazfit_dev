# Промт для ИИ-агента: настройка среды разработки приложений для Amazfit GTS 4 (Ubuntu 24.04 + VS Code)

> Скопируйте текст ниже и передайте его ИИ-агенту (Claude Code, Cursor, Aider и т.п.), работающему на вашей машине с Ubuntu 24.04.

---

## РОЛЬ И ЦЕЛЬ

Ты — DevOps-инженер. Твоя задача: полностью установить, настроить и продиагностировать среду разработки мини-приложений (Mini Programs) и циферблатов для умных часов **Amazfit GTS 4** на платформе **Zepp OS** на компьютере с **Ubuntu 24.04**, с интеграцией в **Visual Studio Code**. После настройки ты обязан выполнить диагностику и выдать отчёт.

Работай автономно, шаг за шагом. Если шаг не удаётся — не прерывай всю работу: зафиксируй ошибку, попробуй обходное решение из раздела «Типичные проблемы», и продолжай.

## СВЕДЕНИЯ О ЦЕЛЕВОМ УСТРОЙСТВЕ (проверено по официальной документации docs.zepp.com)

| Параметр | Значение |
|---|---|
| Модель | Amazfit GTS 4 |
| ОС | Zepp OS 3.5, API_LEVEL 3.6 |
| deviceSource (для app.json) | `7995648` (вариант `7995649`) |
| Форма экрана | Square (квадрат), радиус скругления 86 px |
| Разрешение экрана | 390 × 450 px (AMOLED 1.75") |
| Физические кнопки | 1 |
| Превью циферблата | 266 × 307 px |
| Виджеты (SecondaryWidget) | Поддерживаются |

ВАЖНО про подключение: часы НЕ подключаются к компьютеру по USB (USB у GTS 4 только для зарядки). Установка приложений на часы идёт через QR-код: команда `zeus preview` генерирует QR → на телефоне в приложении Zepp (с включённым режимом разработчика) сканируешь QR → приложение ставится на часы по Bluetooth. НЕ настраивай ADB, udev-правила или USB-отладку — они не нужны.

## ТРЕБУЕМЫЙ СТЕК

1. **Node.js ≥ 18 LTS** (официальный минимум для Zeus CLI — 14+, но используй LTS 20.x) + npm.
2. **Zeus CLI** — официальный инструмент Zepp OS: npm-пакет `@zeppos/zeus-cli` (глобальная установка).
3. **Zepp OS Simulator v2** — эмулятор часов, официальная сборка под Linux (amd64), ставится из .deb-пакета. v2 не требует настройки виртуальных сетевых карт (в отличие от v1).
4. **Visual Studio Code** — редактор; работа через встроенный терминал с командами zeus. Опционально: расширение «Zepp OS Dev Tools» (ID: `Zepp.zeppos-dev-tools`) — ВНИМАНИЕ: официально помечено как deprecated, поддержка прекращена; ставь только как бонус, основной путь — CLI в терминале VS Code.
5. Для публикации приложений позже: аккаунт разработчика на console.zepp.com (регистрация бесплатна, нужна только для выкладки в Zepp App Store; на локальную разработку и установку на свои часы не влияет).

## ПЛАН РАБОТ

### Шаг 1 — Проверка системы и базовые пакеты
- Проверь: `lsb_release -a` (убедись, что Ubuntu 24.04), архитектуру `dpkg --print-architecture` (ожидаю amd64).
- Установи базовые утилиты: `sudo apt update && sudo apt install -y curl git ca-certificates build-essential`.

### Шаг 2 — Node.js LTS
- Проверь `node -v`. Если Node отсутствует или < 18 — установи Node 20 LTS (предпочтительно через nvm: `curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash`, затем `nvm install 20 && nvm use 20`; альтернатива — NodeSource-репозиторий).
- Проверь: `node -v` (v20.x), `npm -v`.

### Шаг 3 — Zeus CLI
- Установи глобально: `npm i @zeppos/zeus-cli -g`.
- Проверь: `zeus -v` — команда должна вывести версию без ошибок. Запомни версию для отчёта.

### Шаг 4 — VS Code
- Если VS Code отсутствует — установи (официальный .deb с packages.microsoft.com или snap: `sudo snap install code --classic`).
- Проверь: `code --version`.
- Опционально: `code --install-extension Zepp.zeppos-dev-tools` (расширение deprecated — если установка падает, просто отметь это в отчёте, это не критично).
- Создай на рабочем столе/в домашней папке каталог проектов: `~/zepp-dev`.

### Шаг 5 — Симулятор Zepp OS (Linux)
- Скачай официальный .deb (v2.1.2, amd64): `https://upload-cdn.zepp.com/zepp-applet-and-wechat-applet/20260717/simulator_2.1.2_linux_amd64.deb`
  (если ссылка устарела — актуальную бери со страницы https://docs.zepp.com/docs/guides/tools/simulator/download/ , раздел «Latest», файл `simulator_*_linux_amd64.deb`).
- Установи: `sudo dpkg -i <файл>.deb; sudo apt -f install -y` (при проблемах с зависимостями).
- Найди, как запускается симулятор (проверь `dpkg -L | grep -i simulator` — список файлов пакета, бинарник/ярлык в /usr/share/applications). Запусти его (через терминал или .desktop) и убедись, что окно открывается. Внутри симулятора отмечу: «Device Simulator» для конкретной модели (GTS 4) докачивается изнутри приложения через «Device Simulator download manager» — если сможешь, проверь наличие загрузчика моделей; саму модель GTS 4 можно оставить на скачивание пользователю, но проверь, что менеджер загрузок открывается.

### Шаг 6 — Тестовый проект
- В каталоге `~/zepp-dev` создай проект: `zeus create hello-world`. Если интерактивные вопросы (тип шаблона, платформы) нельзя ответить в неинтерактивном режиме — используй флаги/параметры CLI или прими ответы по умолчанию; главное — получить каркас проекта.
- Отредактируй `app.json` созданного проекта: в `platforms` укажи целевое устройство GTS 4 — `"name": "gts4", "deviceSource": 7995648` (и/или добавь `7995649`). Убедись, что `configVersion` соответствует API v3.
- Собери проект: `zeus build` — в результате должен появиться пакет `.zab` (обычно в папке `dist`/`build`). Зафиксируй путь к пакету.

### Шаг 7 — Проверка превью (без реальных часов)
- Запусти симулятор (шаг 5), затем в корне проекта `zeus dev` — CLI должен подключиться к симулятору и отобразить приложение. Если симулятор запущен, но `zeus dev` его не видит — перезапусти оба процесса и повтори; зафиксируй результат.
- `zeus preview` — должен сгенерировать QR-код в терминале (установка на реальные часы делается пользователем через телефон; тебе достаточно факта успешной генерации QR).

### Шаг 8 — Диагностика (обязательный финальный чек-лист)
Выполни и собери вывод каждой команды в отчёт:
1. `lsb_release -d` и `dpkg --print-architecture`
2. `node -v && npm -v`
3. `zeus -v`
4. `code --version`
5. Статус симулятора: установлен ли пакет (`dpkg -l | grep -i simulator`), путь до исполняемого файла, запускается ли (факт).
6. Факт успешного `zeus build` (путь к .zab, размер файла).
7. Факт успешного `zeus dev` (подключение к симулятору) и `zeus preview` (QR сгенерирован).
8. Сетевая проверка: `curl -sI https://docs.zepp.com | head -n1` (доступ к инфраструктуре Zepp).

Критерии успеха: пункты 2–8 выполнены без ошибок → среда ГОТОВА. Частично → перечисли, что именно не готово.

### Типичные проблемы и обходные пути
- `zeus -v` падает с ошибками зависимостей → попробуй другую версию Node (18 или 22), переустанови CLI: `npm uninstall -g @zeppos/zeus-cli && npm i @zeppos/zeus-cli -g`. Смотри FAQ: https://docs.zepp.com/docs/guides/faq/
- Симулятор не открывается после dpkg → проверь зависимости `ldd` на бинарнике, установи недостающие библиотеки; проверь запуск из терминала, чтобы видеть ошибки.
- `zeus dev` не видит симулятор → убедись, что симулятор запущен ДО команды, внутри симулятора открыт основной экран; v2 не требует виртуальной сетевой карты (это норма для v1 — не ставь v1).
- Нет GUI/десктопа (headless-сервер) → симулятор требует графическую среду; отметь в отчёте, что превью возможно только с дисплеем или через X-forwarding.
- Не пытайся ставить приложение на часы напрямую из Linux — это делается только через телефон (Zepp App + режим разработчика).

## ЧТО СКАЗАТЬ ПОЛЬЗОВАТЕЛЮ В КОНЦЕ (вручную, без агента)
- На телефоне: установить Zepp App, привязать часы; в приложении: Профиль → Настройки → О приложении → нажать 7 раз на иконку Zepp → появится режим разработчика.
- Установка приложения на часы: `zeus preview` в проекте → отсканировать QR через Zepp App → приложение появится на часах.
- Полезные ссылки: документация https://docs.zepp.com · Quick Start https://docs.zepp.com/docs/guides/quick-start/ · симулятор https://docs.zepp.com/docs/guides/tools/simulator/download/ · консоль разработчика https://console.zepp.com · примеры кода https://github.com/zepp-health
